# Plan: Optimización del Harness Hermes para Interpretación por Modelos

## Problema Actual

Los SOUL.md actuales usan formato narrativo/prosa que es legible para humanos pero no óptimo para interpretación eficiente por modelos de lenguaje. El modelo debe parsear texto descriptivo para inferir reglas de workflow.

## Objetivo

Convertir los protocolos de comunicación y workflow en estructuras declarativas que un modelo pueda parsear directamente sin inferencia.

---

## Optimización 1: STATE_MACHINE Estructurado en Leader SOUL.md

**Cambio**: Agregar sección `## State Machine` al inicio del documento (después de Identity) con tabla declarativa de estados y transiciones.

```
## State Machine — Kanban

| Estado | Entrada desde | Salida a | Acción requerida |
|--------|---------------|----------|-------------------|
| INBOX  | subagentes    | ARCHIVE  | Procesar reporte → archivar |
| TODO   | leader        | IN_PROGRESS | Asignar a subagente |
| IN_PROGRESS | TODO | REVIEW/DONE/BLOCKED | Claim → trabajar → reportar |
| REVIEW | IN_PROGRESS | DONE/IN_PROGRESS | Revisar → APPROVED/CHANGES_REQUESTED |
| BLOCKED | cualquier | TODO | Resolver impedimento |
| DONE   | REVIEW/IN_PROGRESS | ARCHIVE | Validado → archivar |
```

**Beneficio**: El modelo lee una tabla y sabe exactamente qué acciones tomar en cada estado.

---

## Optimización 2: COMMAND_PROTOCOLS en cada SOUL.md de Subagente

**Cambio**: Agregar sección `## Command Protocol` como bloque YAML estructurado.

```yaml
## Command Protocol

trigger:
  condition: "task completed or blocked"
  check: "hermes kanban list | grep <profile>"

actions:
  - step: 1
    command: "hermes kanban create"
    args: ["<ESTADO> -> TASK-<XXX>: <resumen>"]
    target: INBOX
  - step: 2
    command: "hermes kanban assign"
    args: ["<id_nuevo>", "leader"]
    target: INBOX
  - step: 3
    command: "hermes kanban complete|block"
    args: ["<id_original>"]
    target: tareas original
```

**Beneficio**: El modelo ejecuta comandos directamente de estructura, sin interpretar prosa.

## Optimización 3: Tabla de Estados por Perfil

**Cambio**: Agregar `## Profile States` en cada SOUL.md con tabla simple:

```
## Profile States

| Mi estado | Lo que envío al Leader | Cmd que ejecuto |
|-----------|------------------------|-----------------|
| DONE | "DONE -> TASK-XXX: resumen" | hermes kanban create + assign + complete |
| BLOCKED | "BLOCKED -> TASK-XXX: causa" | hermes kanban create + assign + block |
| STUCK | "STUCK -> TASK-XXX: necesito ayuda" | hermes kanban create + assign |
```

**Beneficio**: Vista tabular de una línea que replace la sección "Comunicación con el líder" actual.

## Optimización 4: WORKFLOW.md Global

**Cambio**: Crear archivo `/home/elegro/.hermes/WORKFLOW.md` estructurado como máquina de estados legible por modelo.

Contenido:
- Diagrama de flujo en texto estructurado
- Tablas de transición de estado por tipo de agente
- Comandos exactos por cada transición
- Formato de mensajes entre agentes

**Beneficio**: Archivo único que define todo el workflow sin narrativa.

---

## Implementación Propuesta

1. **Leader**: Agregar `## State Machine` y `## Profile States` al inicio del SOUL.md
2. **Subagentes** (coder, reviewer, researcher, assistant):
   - Agregar `## Command Protocol` estructurado
   - Agregar `## Profile States` simplificado
3. **Crear** `WORKFLOW.md` como referencia única estructurada

---

## Resultado Esperado

- Modelo puede parsear workflow en 1-2 tabla en lugar de 10+ párrafos de prosa
- Menos ambigüedad en interpretación de reglas
- Más fácil agregar nuevos perfiles o modificar transiciones
- Documentación同人-friendly mantiene compatibilidad con SOUL.md actuales
